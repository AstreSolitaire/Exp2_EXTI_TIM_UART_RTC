## 一、总体数据流

```
                       ┌──────────── EXTI0 中断（按键按下，上升沿）────────────┐
B1(PA0) ──跳变──→ EXTI ─┤ HAL_GPIO_EXTI_Callback: s_dirReverse 取反          │
                       │                        snprintf 生成 [EXTI0] 字符串  │
                       └────────────────── 置 s_keyMsgFlag ───────────────────┘
                                        │
TIM3 ──250 ms──→ 更新中断 ──→ HAL_TIM_PeriodElapsedCallback ──→ Led_Marquee_Step()
                                        │                        （按 s_dirReverse 正/反向）
                                        │
PC ─串口→ PA3 ─→ USART2 RXNE 中断 ─→ HAL_UART_RxCpltCallback
                                   └→ Frame_RxByte() 逐字节组帧
                                        └→ g_frameRdy=1
                                             │
主循环 while(1) ──────────────────────────────┼─→ 发送 s_keyMsg
                                              ├─→ 解析帧 → Frame_DecodeSetRtc() → 写 RTC
                                              └─→ 发送 RTC 秒中断准备好的时间字符串

RTC 1 Hz 唤醒中断 ─→ 读时间/日期 → 格式化 → g_rtcSecFlag=1 ──┘
```

## 二、初始化顺序（main.c）

```c
HAL_Init();                  // SysTick 1ms 时基、NVIC 分组 4、HAL_MspInit
SystemClock_Config();        // HSE 8M → PLL(8,336,2) → 168 MHz；APB1 42M / APB2 84M
MX_GPIO_Init();              // LED 输出；PA0 = IT_RISING + 下拉（EXTI0）
MX_RTC_Init();               // LSI 时源、1Hz 分频、写初值、开秒中断
MX_TIM3_Init();              // 250 ms 时基（PSC 8399 / ARR 2499）
MX_USART2_UART_Init();       // 9600-8-N-1，PA2/PA3 复用 AF7
Uart_DmaInit();              // ★ 串口 TX/RX 的 DMA 通道（必须在第一次 printf 之前）
HAL_TIM_Base_Start_IT(&htim3);                     // ★ 启动定时器更新中断（CubeMX 不会自动加）
HAL_UARTEx_ReceiveToIdle_DMA(&huart2, g_uartRxDma, 64);  // ★ 挂上 RX 的 DMA+IDLE 接收
```

顺序依赖：时钟→外设；RTC 的时源在 MspInit 里（需先解锁备份域）；
`Uart_DmaInit` 必须在任何串口发送之前（否则 `hdmatx` 为空会 HardFault）；
`HAL_TIM_Base_Start_IT` 与 `HAL_UARTEx_ReceiveToIdle_DMA` 必须显式调用，否则中断不会来。

## 三、按键外部中断（EXTI0）

### 3.1 硬件与配置

```c
/* gpio.c —— CubeMX 生成 */
GPIO_InitStruct.Pin  = B1_Pin;              // PA0
GPIO_InitStruct.Mode = GPIO_MODE_IT_RISING; // 上升沿触发中断
GPIO_InitStruct.Pull = GPIO_PULLDOWN;       // 松手=低，按下=高 → 按下瞬间产生上升沿
/* 同时生成：HAL_NVIC_SetPriority(EXTI0_IRQn, 1, 0); HAL_NVIC_EnableIRQ(EXTI0_IRQn); */
```

### 3.2 中断链路（三级）

```c
/* stm32f4xx_it.c —— 第 1 级：向量表入口 */
void EXTI0_IRQHandler(void)
{
  HAL_GPIO_EXTI_IRQHandler(B1_Pin);        // 第 2 级：HAL 清 EXTI 挂起位
}

/* main.c —— 第 3 级：用户回调（HAL 内部调用） */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  if (GPIO_Pin == B1_Pin)
  {
    s_dirReverse = (s_dirReverse == 0U) ? 1U : 0U;      // 顺时针 ↔ 逆时针
    snprintf(s_keyMsg, sizeof(s_keyMsg),                // 生成中断信息（不阻塞）
             "[EXTI0] B1 pressed -> %s\r\n",
             (s_dirReverse != 0U) ? "COUNTER-CLOCKWISE (LD3->LD4->LD6->LD5)"
                                  : "CLOCKWISE (LD3->LD5->LD6->LD4)");
    s_keyMsgFlag = 1U;                                  // 交给主循环发送
  }
}
```

**为什么不在中断里直接 printf**：9600 bps 下 40 字符 ≈ 42 ms，中断里阻塞这么久，
TIM3 的 250 ms 节拍会被推迟、串口接收也可能丢字节。中断里只做微秒级工作
（改标志 + 内存里拼字符串），发送放主循环——这就是“中断快进快出”原则。

## 四、定时器 TIM3（250 ms 节拍）

### 4.1 参数推导

```
TIM3 时钟 = APB1 定时器时钟 = PCLK1 × 2 = 42 MHz × 2 = 84 MHz
（APB1 分频 ≠1 时，定时器时钟自动 ×2，这是 F4 的规则）

PSC = 8399  → 计数频率 = 84 MHz / (8399+1) = 10 kHz
ARR = 2499  → 溢出周期 = (2499+1) / 10 kHz = 250 ms   ← 在要求的 200~500 ms 区间
```

改节拍只需要改 ARR：200 ms→1999，300 ms→2999，500 ms→4999。

### 4.2 启动与回调

```c
/* main.c 初始化段 */
HAL_TIM_Base_Start_IT(&htim3);   // 使能 CEN=1 且 UIE=1

/* main.c 回调：每 250 ms 进一次 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
  if (htim->Instance == TIM3)
  {
    Led_Marquee_Step();          // 只看方向，不做延时
  }
}
```

### 4.3 顺时针 / 逆时针实现

**先看 LED 的物理位置**——四颗灯不是一排，而是菱形：

```
            LD3 (PD13)  ← 上
 LD4 (PD12)              LD5 (PD14)   ← 左 / 右
            LD6 (PD15)  ← 下
```

若按名字 `{LD3, LD4, LD5, LD6}` 依次点亮，路径是「上→左→右→下」，
灯会来回横跳，看起来就是 **Z 字形**。所以数组必须按物理绕圈顺序定义：

```c
/* 顺时针绕圈：LD3(上) → LD5(右) → LD6(下) → LD4(左) */
static const uint16_t s_ledRing[4] = {LD3_Pin, LD5_Pin, LD6_Pin, LD4_Pin};
static volatile uint8_t s_ledIndex = 0;    // 0→LD3 1→LD5 2→LD6 3→LD4
static volatile uint8_t s_dirReverse = 0;  // 0 顺时针 / 1 逆时针

static void Led_Marquee_Step(void)
{
  Led_AllOff();                                        // 先全灭，保证只亮一盏
  HAL_GPIO_WritePin(GPIOD, s_ledRing[s_ledIndex], GPIO_PIN_SET);
  if (s_dirReverse == 0U) {                            // 顺时针：序号递增
    s_ledIndex = (s_ledIndex + 1U) & 0x03U;            // 0→1→2→3→0（上→右→下→左）
  } else {                                             // 逆时针：序号递减
    s_ledIndex = (s_ledIndex == 0U) ? 3U : (uint8_t)(s_ledIndex - 1U);  // 上→左→下→右
  }
}
```

`& 0x03` 等价于 `% 4`（4 是 2 的幂，位运算更快），这是嵌入式常见写法。

> 改方向只需换数组：若某块板的 LED 排列与本图不同，按实际位置重排
> `s_ledRing` 即可，`s_ledIndex` 的加减逻辑不用动。

## 五、串口数据帧接收与解析

### 5.1 帧格式

```
 $   0   ,   1   ,  251107  ,  140101   *
 ↑   ↑       ↑      ↑          ↑        ↑
帧头 地址  命令1=设时间  YYMMDD   HHMMSS   帧尾
```

### 5.2 逐字节状态机（USART2 接收中断里调用）

```c
static uint8_t Frame_RxByte(uint8_t rx)
{
  if (rx == '$') { s_rxInFrame = 1; s_rxLen = 0; return 0; }   // 帧头：重新开始
  if (!s_rxInFrame) return 0;                                   // 帧外字节：丢弃
  if (rx == '*') { s_rxInFrame = 0; chRxBuf[s_rxLen] = 0; return 1; }  // 帧尾：完成
  if (s_rxLen < sizeof(chRxBuf) - 1) { chRxBuf[s_rxLen++] = rx; return 0; }
  s_rxInFrame = 0; s_rxLen = 0; return 0;                       // 超长帧：丢弃防溢出
}
```

设计要点：
- 只认 `$...*` 之间的内容，杂散字符自动忽略 → 从串口助手粘贴时前面带换行也不影响；
- 缓冲区写满即丢弃整帧（而不是覆盖），保证内存安全；
- 返回 1 表示“一帧完整”，由回调置 `g_frameRdy`，主循环负责解析（解析较慢，不占中断）。

### 5.3 解析与写 RTC

```c
sscanf(buf, "%d%*[ ,]%d%*[ ,]%d%*[ ,]%d", &nAddr, &nCmd, &nYMD, &nHMS);
// %*[ ,] = 读掉一个或多个空格/逗号（星号表示不保存）

nY = nYMD / 10000;      // 251107 / 10000     = 25
nM = nYMD % 10000 / 100;// 251107 % 10000/100 = 11
nD = nYMD % 100;        // 251107 % 100       = 7
nH = nHMS / 10000; nMin = nHMS % 10000 / 100; nS = nHMS % 100;

/* 范围检查：月份 1~12、日 1~31、时 0~23、分/秒 0~59，非法直接丢弃 */
/* HAL_RTC_SetTime(RTC_FORMAT_BIN) 写时分秒 */

/* 日期寄存器必须带星期：用 Sakamoto 公式算 */
static const uint8_t t[] = {0,3,2,5,0,3,5,1,4,6,2,4};
if (month < 3) y--;
w = (y + y/4 - y/100 + y/400 + t[month-1] + day) % 7;  // 0=周日
weekday = (w == 0) ? RTC_WEEKDAY_SUNDAY : w;            // 转成 1~7
/* HAL_RTC_SetDate(RTC_FORMAT_BIN) 写年月日+星期 */
```

写完后立刻 `printf("[RTC] updated -> 20YY-MM-DD HH:MM:SS")`，
随后每秒上传的 RTC 行就是新时间——这就是“上传数据核对是否改对”。

### 5.5 串口 DMA 收发（本工程实现）

#### 为什么改

轮询发送 22 字节 @9600 ≈ 23 ms，主循环在这段时间里干不了别的；
`printf` 每字符一次阻塞调用。改成 DMA 后，CPU 只负责“把数据放进缓冲并启动搬运”，
搬字节由 DMA 硬件完成，**发送调用立即返回**。

#### TX：环形 FIFO + DMA 链式发送

```c
#define UART_TX_FIFO_SIZE 512
#define UART_DMA_CHUNK    128

static uint8_t s_txFifo[512];            // 上层写入
static uint8_t s_dmaTxBuf[128];          // ★ DMA 源缓冲，必须静态！
static volatile uint16_t s_txHead, s_txTail;
static volatile uint8_t  s_txBusy;

int fputc(int ch, FILE *f) { return Uart_TxChar(ch); }   // printf 只入队

void Uart_Kick(void)                      // 取一块数据启动 DMA
{
  if (s_txBusy) return;
  if (huart2.gState != HAL_UART_STATE_READY) return;   // ★ 只看 gState
  if (s_txHead == s_txTail) return;

  __disable_irq();                        // 临界区：主循环与 TxCplt 都可能调用
  n = Fifo_Pop(s_dmaTxBuf, 128);
  if (n) s_txBusy = 1;
  __enable_irq();

  if (n && HAL_UART_Transmit_DMA(&huart2, s_dmaTxBuf, n) != HAL_OK) s_txBusy = 0;
}

void HAL_UART_TxCpltCallback(UART_HandleTypeDef *h)   // 一块发完，接着发
{
  if (h->Instance == USART2) { s_txBusy = 0; Uart_Kick(); }
}
```

#### RX：DMA + 空闲(IDLE)中断

```c
uint8_t g_uartRxDma[64];                                     // ★ 静态缓冲

HAL_UARTEx_ReceiveToIdle_DMA(&huart2, g_uartRxDma, 64);      // 主循环启动一次

void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *h, uint16_t Size)
{
  if (h->Instance == USART2) {
    if (App_FrameFeed(g_uartRxDma, Size)) g_frameRdy = 1;    // 整段交给帧状态机
    HAL_UARTEx_ReceiveToIdle_DMA(&huart2, g_uartRxDma, 64);  // 重新挂接收
  }
}
```

好处：不再“每字节一次中断”，而是一段数据（总线空闲）进一次中断；
帧状态机改成 `App_FrameFeed(buf, len)` 循环处理整段，跨段的半帧也能接上
（状态 `s_rxInFrame/s_rxLen` 是静态的，跨段保持）。

#### 两个真实踩过的坑

| 坑 | 现象 | 原因与修正 |
|---|---|---|
| 用 `HAL_UART_GetState()` 判断能否发送 | 完全无输出，FIFO 堆到 511 B，`USART2.CR3.DMAT=0`、`DMA1_Stream6.NDTR=0` | 该函数返回 **`gState \| RxState` 组合值**；RX 常开 DMA 时永远不等于 `READY`。改为只判断 `huart2.gState` |
| DMA 初始化晚于第一次 printf | 上电即 HardFault（无任何输出） | `HAL_UART_Transmit_DMA` 会解引用 `huart->hdmatx`；把 `Uart_DmaInit()` 挪到 USER CODE 2 最前面 |

另外，DMA 源缓冲必须静态/全局——若用栈上局部数组，函数返回后内容被覆盖，发出的是乱码。

## 七、中断优先级设计

| 中断 | 抢占优先级 | 理由 |
|---|---|---|
| RTC_WKUP | 0（最高） | 1 Hz 时间基准，不能被任何慢事务推迟 |
| EXTI0 | 1 | 按键响应要快，但可让位于时间基准 |
| USART2 | 1 | 9600 bps 一字节约 1 ms，必须及时取走 |
| TIM3 | 2 | 250 ms 节拍，稍有延迟无影响 |

优先级数字越小越优先（NVIC 分组 4：4 位全是抢占优先级）。

## 九、实测结论（上板）

- TIM3：`PSC=8399 / ARR=2499` → 实测周期 250.0 ms，`CEN=1, UIE=1`；
- 顺时针：ODR 连续采样得 LD3→LD5→LD6→LD4（上→右→下→左）循环；
- 软件触发 EXTI0（写 `EXTI_SWIER`）后 `s_dirReverse` 0→1，且
  `s_keyMsg = "[EXTI0] B1 pressed -> COUNTER-CLOCKWISE (LD3->LD4->LD6->LD5)"`，逆时针顺序 LD3→LD4→LD6→LD5；
- 注入 `$0,1,251107,140101*` 后：`chRxBuf="0,1,251107,140101"`、
  `RTC_TR=0x00140101`（14:01:01）、`RTC_DR` 年月日=2025-11-07、weekday=5（周五），
  之后逐秒上传的正是 14:01:1x —— 帧解析与 RTC 更新链路正确。
